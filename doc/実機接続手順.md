# Go2 実機接続手順

`go2_follow.py` を Go2 実機につないで動かすまでの手順。2026-10-05 に実機で接続・映像受信・手の検出まで確認済み。

## 構成

- 接続方式: WebRTC（`unitree_webrtc_connect` 2.2.0、LocalSTA = Go2 と Mac を同じ Wi-Fi/LAN につなぐ方式）
- Go2 のファームウェアが新しい（1.1.15 以降）ため、**機体ごとの AES キーが必須**

| 項目 | 今回の値 |
|---|---|
| Mac のネットワーク | `192.168.10.x` |
| Go2 の IP | `192.168.10.154`（DHCP のため変わることがある） |
| Go2 シリアル番号 | `B42D1000Q7L8N6G3`（alias: `Go2_62754`） |
| AES キー | 秘密情報のためここには書かない（取得方法は手順 3） |

## 手順

### 1. 仮想環境を有効にする

必ず `go2-hand-follow/` フォルダで `.venv` を有効にしてから実行する。

```bash
cd ~/Documents/doglog/go2-hand-follow
source .venv/bin/activate
```

有効にしないと、mise の `python` が呼ばれて `No version is set for shim: python` というエラーになる。

### 2. Go2 の IP を調べる

Go2 と Mac を同じネットワークにつなぎ、Unitree Go アプリかルーターの管理画面で Go2 の IP を調べる。

わからないときは、Go2 が接続の受け付けに使うポート 9991 を開けている機器を探す。

```bash
for i in $(seq 1 254); do (nc -z -G 1 192.168.10.$i 9991 2>/dev/null && echo "192.168.10.$i") & done; wait
```

- `192.168.10` の部分は Mac のネットワークに合わせる（`ipconfig getifaddr en0` で確認できる）。
- ライブラリの自動検出（マルチキャスト）では見つからなかった。
- 今回は `.154` と `.155` の2台が見つかり、接続テストの結果 `.154` が Go2 だった。

### 3. AES キーを取得する

Unitree Go アプリと同じアカウントで、キーを取得する。

```bash
unitree-fetch-aes-key --email <アカウントのメールアドレス> --device-type Go2
```

- **`--device-type Go2` を付けないと、G1 用のアカウントが検索されて `0 devices` になる。**
- 一覧の `AES-128 key` の列にある 32桁の値がキー。
- パスワードの入力があるので、自分のターミナルで実行する。

### 4. Unitree Go アプリを完全に終了する

Go2 は WebRTC で同時に1台しかつながらない。アプリがつながったままだと `RobotBusyError` になる。

- アプリはバックグラウンドに残さず、上にスワイプして閉じる。
- それでもエラーが出るときは、10〜20秒待ってから実行し直す。
- Go2 が伏せているときは、アプリで先に立たせてからアプリを閉じる。

### 5. dry-run で確認する（ロボットは動かない）

```bash
python go2_follow.py --ip 192.168.10.154 --aes-key <32桁のキー> --dry-run
```

確認すること:

1. 「接続OK」と出て、Go2 のカメラ映像のウィンドウが開く
2. 手を開いて見せると、`Forward` / `Turn` の値が変わって文字が緑色になる
3. グーにすると、値が 0 に戻って文字が赤色になる
4. 2行目に処理 fps が出る（目安は 15 以上）。低いときは手の認識が追いつかない

### 6. 実際に動かす

周りに人や物がない広い場所で、すぐ止められる状態にしてから実行する。

```bash
python go2_follow.py --ip 192.168.10.154 --aes-key <32桁のキー>
```

| 操作 | 動き |
|---|---|
| 手を開く | 追従する |
| 手が小さく映る（遠い） | 前に進む |
| 手が大きく映る（近い） | 下がる |
| 手が画面の左右に寄る | その方向に回る |
| グーにする / 手が映らなくなって 0.5 秒たつ | 止まる |
| ESC キー | 止まってから終了する |

速さは `hand_control.py` で調整する。`MAX_VX` は前後の最大速度（今は 0.35 m/s）、`K_FWD` / `K_YAW` は反応の強さ。

## お手・おすわりデモ（`go2_trick.py`）

接続の準備（手順 1〜4）は追従デモと同じ。

### 実機なしで試す（Mac のウェブカメラ）

```bash
python go2_trick.py --webcam 0
```

- ロボットには接続せず、何も送らない。ジェスチャーの判定と画面表示だけを確かめられる。
- 「カメラ 0 を開けません」と出たら、`--webcam 1` のように番号を変える。
- 初回は macOS がカメラの使用許可を求めるので、ターミナル（または VS Code）を許可する。

### 実機で動かす

Go2 を**立たせた状態**で起動する。座っているか立っているかはプログラムが覚えているだけなので、起動したあとにアプリやリモコンで姿勢を変えると、表示と実際の姿勢がずれる。

```bash
# まず dry-run で判定を確認（ロボットは動かない）
python go2_trick.py --ip 192.168.10.154 --aes-key <32桁のキー> --dry-run
# 問題なければ
python go2_trick.py --ip 192.168.10.154 --aes-key <32桁のキー>
```

### 操作

同じジェスチャーを **1秒続ける**と指示になる（画面に判定の進み具合が % で出る）。動作中の **4秒間**は次の指示を受け付けない（画面に `BUSY` と残り秒数が出る）。同じジェスチャーで続けて指示するには、一度手を下ろすか形を変える（出し続けても繰り返さない）。すでにその姿勢のとき（立っているときのグーなど）は何も動かないので、BUSY にならない。

| ジェスチャー | キー | 動作 |
|---|---|---|
| パー | `h` | その場でお手（Hello、右前足）。座っていれば先に立つ |
| 人差し指だけ（中指は軽く曲げればよい） | `s` | おすわり（Sit） |
| グー | `u` | 立つ（RiseSit） |
| チョキ | `v` | ハート（FingerHeart）。座っていれば先に立つ |
| — | ESC | 終了 |

指の判定:

- 指ごとに、第二関節の曲がり具合を奥行きも含めた 3D の角度で判定する。人差し指をカメラの方へ向けても、伸びていると判定できる。
- 画面の `I M R P` の行に、人差し指・中指・薬指・小指の曲がり具合（cos）が出る。+1.0 に近いほどまっすぐ、0 以下は大きく曲がっている。0.6 より大きいと「伸び」、0.2 より小さいと「曲げ」とみなす。認識がうまくいかないときは、ここを見てどの指の値がずれているか確かめる。
- おすわりの中指は 0.45 より小さければよい（軽く丸めるだけでよい）。ハートの中指は 0.6 より大きい必要がある。0.45〜0.6 はどちらとも判定しない。
- チョキなど、どれにも当てはまらない形は無視する。
- 判定が 0.3 秒以内だけ揺れても、同じジェスチャーを続けているとみなす（`GRACE_SEC`）。

お手について:

- **高さ:** 手の高さに制限はなく、どの高さでも受け付ける。ただし Go2 の足が届く高さは決まっているので、高すぎる手には届かない。
- **その場で行う:** お手のときは Go2 は動かない（手に近づいたり向き直ったりしない）。手の位置は自分で合わせる。Go2 は**右前足**でお手をするので、右前足の少し前、足が下りてくる位置からずらして手を出す。手を追いかけさせたいときは追従デモ（`go2_follow.py`）を使う。
- 以前は手に合わせて前後・左右に動いてからお手をしていたが、近づきすぎて怖く、足を下ろすときに手に当たったため、その場で行う形に変えた。
- **座っているとき:** 先に立ち上がり、約2秒後にお手をする。
- 手のパーが映っていないフレームでは動かさない。手を見失ったら止まる。
- Go2 のお手は決まった動きを再生するだけなので、足を上げる高さや方向はコードから変えられない。

### 調整する値

| 値 | ファイル | 今の値 | 意味 |
|---|---|---|---|
| `HOLD_SEC` | `go2_trick.py` | 1.0 | ジェスチャーを何秒続けたら指示にするか |
| `ACTION_SEC` | `go2_trick.py` | 4.0 | 動作中に次の指示を受け付けない秒数 |
| `GRACE_SEC` | `go2_trick.py` | 0.3 | 判定がこの秒数以内だけ揺れても、続けているとみなす |
| `SIT_MIDDLE_COS` | `go2_trick.py` | 0.45 | おすわりで中指がこれより小さければよい（約63°以上の曲がり）。大きくすると、おすわりになりやすいがチョキと間違えやすくなる |
| `EXTENDED_COS` / `FOLDED_COS` | `hand_control.py` | 0.6 / 0.2 | 指が伸びている／曲がっているとみなす角度のしきい値（それぞれ約53°以内／約78°以上の曲がり） |

`ACTION_SEC`（4秒）と、座った状態からお手をするときの立ち上がりの待ち時間（2秒）は仮の値で、実機ではまだ確かめていない。

## 白飛びするとき（`--gamma`）

Go2 のカメラの露出はコードから変えられない。明るい場所で手が白く飛ぶときは、手の検出の前に明るさを補正する（追従デモ・お手おすわりデモ共通）。

```bash
python go2_follow.py --ip <IP> --aes-key <キー> --gamma 2.0
python go2_trick.py  --ip <IP> --aes-key <キー> --gamma 2.0
```

- 1.0 で補正なし。1.5〜2.5 で、全体を暗くして明るい部分の明暗差を広げる。画面には補正後の映像が出る。
- 画面の `white xx%` は、補正前の映像で白飛び（ほぼ真っ白）している画素の割合。
- **真っ白になった部分は情報が残っていないので戻せない。** `white` が高いときは、窓や照明を背にしない、直射日光を避ける、などカメラ側の環境を変える方が効く。

## トラブルシューティング

| エラー・症状 | 原因 | 対処 |
|---|---|---|
| `mise ERROR No version is set for shim: python` | `.venv` を有効にしていない | 手順 1 |
| `LocalSignalingPortError ... not exposing a signaling port` | IP が違う、または Go2 が別のネットワークにいる | 手順 2 で IP を調べ直す |
| `AesKeyRequiredError` | `--aes-key` を付けていない | 手順 3 |
| `unitree-fetch-aes-key` の結果が `0 devices` | `--device-type Go2` を付けていない | `--device-type Go2` を付ける。それでも出ないときは、アカウントや機体の登録を確かめる |
| `RobotBusyError` | アプリなど、ほかのクライアントが接続中 | 手順 4 |
| `NoSdpAnswerError` | 指定した IP が Go2 ではない（今回の `.155`） | 別の IP で試す |
| 映像が来ない | 接続の直後、または Go2 の起動中 | 数秒待つ。起動から約1分待つ |
